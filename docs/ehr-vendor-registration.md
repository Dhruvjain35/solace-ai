# EHR Vendor Registration — Epic / Oracle Health / Athenahealth

Paste-ready registration profile + per-vendor steps for connecting Solace as a
provider-facing SMART-on-FHIR app. Grounded in `backend/lib/ehr_vendors.py`,
`backend/routers/ehr_auth.py`, and 2026 vendor-portal research.

> Status legend: ✅ confirmed in our code · ⚠️ verify directly with the vendor before submitting.

---

## 1. Solace app profile (identical across all three vendors)

| Field | Value |
|---|---|
| App type | Provider-facing SMART-on-FHIR (EHR launch + standalone) |
| FHIR version | R4 |
| **Redirect URI** | `https://djfjrel7b1ebi.cloudfront.net/api/auth/ehr/callback` |
| **JWKS URL** | `https://djfjrel7b1ebi.cloudfront.net/.well-known/jwks.json` |
| Client auth | Public client (PKCE) for sandbox · confidential `private_key_jwt` (RS384/JWKS) for production |
| PKCE | Required (S256) |
| Signing alg | **RS384**, RSA-2048 (✅ matches Epic's requirement) |
| **Scopes (SMART v2)** | `openid fhirUser launch online_access profile user/Patient.rs user/Practitioner.rs user/Encounter.rs user/Observation.rs user/MedicationRequest.rs user/AllergyIntolerance.rs user/Condition.rs` |
| Scopes (v1 fallback) | same identity scopes + `user/<Resource>.read` |
| Data posture | Read + search only (minimum-necessary, HIPAA §164.502(b)) — no write/create/delete requested |

**Signing key:** generated by `scripts/setup_ehr_signing_key.py --vendor <epic|cerner|athena>`.
Private key → `backend/.secrets/` (gitignored) → AWS Secrets Manager (`solace/ehr/<vendor>-private-key`).
Public key → served at the JWKS URL above via `SOLACE_EHR_JWKS`. Wire per vendor with
`SOLACE_<VENDOR>_PRIVATE_KEY` (PEM) + `SOLACE_<VENDOR>_KID`.

## 2. Per-vendor steps

### Epic on FHIR
1. Register the app at **fhir.epic.com/Developer/Apps** (free, self-service). You get
   non-prod + prod client IDs immediately and a sandbox against synthetic data.
2. Set the redirect URI + register the **JWKS URL** (Epic accepts a JWKS URI or an
   uploaded X.509 public key; ✅ requires RS384 — we comply).
3. Set `SOLACE_EPIC_CLIENT_ID` (+ the private key/kid env) and flip
   `SOLACE_EPIC_SANDBOX=false` only when pointing at a real tenant.
4. **Production:** Epic **Vendor Services** membership (~$1,900/yr ⚠️) + a **Showroom /
   Connection Hub** listing — reviewed (questionnaire → security → FHIR compliance),
   **8–16 weeks** ⚠️. BAA is executed **with each provider organization**, not Epic.

### Oracle Health (formerly Cerner)
1. Free **CernerCare** account → register the app in **code Console**
   (`code-console.cerner.com`). Build on **FHIR R4 (Ignite)**, not DSTU2.
2. Register as a **System / Confidential** app and upload your **JWKS via the System
   Account Management portal** (✅ asymmetric `private_key_jwt` supported).
3. Set `SOLACE_CERNER_CLIENT_ID` (+ key/kid).
4. **Production:** not self-service — the **customer files a Service Request** for
   "Cerner Ignite APIs for Millennium" (+ possibly a **PECA** form) to provision your
   client ID against their tenant. BAA with the provider org. Dev/test env via Oracle
   PartnerNetwork reported ~$5,000 ⚠️.

### Athenahealth
1. Create an account at **mydata.athenahealth.com**, create an application → Client
   ID/Secret. Sandbox is **instant + free** (synthetic data). ⚠️ **V22 sandbox retires
   May 1, 2026** — use the current version.
2. ⚠️ **Open risk:** public docs only confirm **client-ID/secret** (symmetric) backend
   auth — `private_key_jwt`/JWKS support is **unconfirmed**. Verify before relying on
   our RS384/JWKS path; we may need a `client_secret` (symmetric) config for Athena.
3. Set `SOLACE_ATHENA_CLIENT_ID` (+ secret or key per the above).
4. **Production:** list on the **athenahealth Marketplace** — technical + security + UX
   + compliance review (BAA executed **via athenahealth**), **6–12 weeks** ⚠️, typically
   a **Platform Services contract + 15–30% revenue share** ⚠️.

## 3. Reliability flags (don't treat as gospel — verify)
- Epic fees/timelines and Oracle prod pricing come from third-party 2026 guides, not
  official pricing pages.
- Athenahealth asymmetric/JWKS support is **unverified** — the one item that could
  break the shared RS384/JWKS design.
- Sandbox (free, fast, synthetic) is available today for all three; **production = review
  + BAA + real PHI** and is the long pole.

## 4. Security prerequisites before real creds go live
- C3 SSRF guard (`lib/url_guard.py`) — ✅ shipped on this branch.
- ⚠️ Harden the two open HIGHs first: id_token soft-fallback on discovery failure, and
  the FHIR access_token currently embedded in the client-held Solace JWT.
- ⚠️ Admin-gate the `PUT /workspaces/{id}/ehr-config` write (currently any clinician role).
